# Schema Strategy

| Status | Owner | Stage | Date |
|---|---|---|---|
| Implemented in the build; validation in Stage 9 | schema-specialist | 4 / 9 | 2026-09-20 |

All JSON-LD is generated by `scripts/build.mjs` from `config/business.json`. **A property is emitted only when its source fact is `verified: true`.** Nothing is hand-written per page, so the graph cannot drift from the business data.

## Entity graph
| `@id` | Type | Where |
|---|---|---|
| `https://alqasimmovers.com/#business` | `MovingCompany` (a LocalBusiness subtype) | Every page |
| `https://alqasimmovers.com/#website-{lang}` | `WebSite` | Home page of each language |
| — | `Service` | Service pages (`"type": "service"` + `serviceName` in the page meta) |
| — | `BreadcrumbList` | Any page that declares `breadcrumbs` |

## MovingCompany properties
| Property | Source | Emitted now? |
|---|---|---|
| `name` | `name` / `nameArabic` on Arabic pages | Yes |
| `url` | domain + language root | Yes |
| `telephone` | `phone.e164` | Yes |
| `image` | the square mark | Yes |
| `address` | locality/region/country | Yes (no `streetAddress` — not verified) |
| `areaServed` | Dubai + the six other emirates | Yes |
| `email`, `streetAddress`, `geo`, `openingHours`, `sameAs`, `priceRange` | owner data | **No** — added automatically the moment the owner verifies them |
| `aggregateRating`, `review` | — | **Never** self-served. Only real, visible reviews, and no self-serving rating markup on our own business. |

## Rules
- `FAQPage` markup only on pages with visible Q&A, and only where current Google rules make it worthwhile. Being ineligible for rich results is never a reason to create or pad a page.
- Arabic pages carry Arabic text values and `inLanguage: "ar"`, but share the same business `@id` so both languages describe one entity.
- No `Product` or `Offer` markup for services (competitors do this; it is the wrong type and invites price/rating markup we cannot honestly supply).

## Validation (Stage 9)
Run every template through the Google Rich Results Test and validator.schema.org; record results and screenshots in `docs/audits/technical-seo-audit.md`. Target: zero errors, and zero warnings that relate to invented data.
